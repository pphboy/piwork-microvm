# Spec Delta

## ADDED Requirements

### Requirement: 两平台主入口承受浏览器并发连接

Windows 和 Linux MicroVM 的 UI 与 Core 回环转发 SHALL 支持浏览器启动期间的并发新 TCP 连接，不能因转发监听队列过小而拒绝或长期延迟正常的六路并发。现有两个 IPv4 回环监听、默认／自定义端口、Guest 映射、Host/Origin、CSRF、权限与 Service 网络边界 SHALL 保持不变，不增加 Host 代理、额外入口或外部监听。

用于确认本能力的真实 Windows／Linux Host 和 Guest 验收 SHALL 使用已就绪的各平台最终打包产物，对 UI、Core 两个端口分别完成不自动重试的原生请求验证：串行 30 次，以及五批、每批同时建立 6 条新 TCP 连接共 30 次；所有连接均成功并收到对应服务的预期 HTTP 响应，无连接拒绝、悬挂或请求超时。验证 SHALL 禁用连接复用与请求重试，分别记录成功数、拒绝、其他连接错误和超时；不能用页面自动恢复、单个长连接、另一平台转发出的请求或伪造 HTTP 服务代替对应平台 Host 到真实 Guest 的测量。此验收用于确认并记录实际能力，不改变既有不以真实平台验收为前置条件的发布快门槛。

#### Scenario: 选定端口并发加载
- **WHEN** 用户以两个可用的默认或自定义端口启动已就绪的最终 MicroVM，并从对应平台原生 Host 对所选 UI 与 Core 端口分别运行串行与六路并发测量
- **THEN** 两端口各自的 30 次串行和 30 次并发请求均成功，零连接拒绝、其他连接错误与超时；原版登录和 Desktop 资源可通过 UI 入口加载。

#### Scenario: 自定义端口保持转发边界
- **WHEN** 用户为 UI 与 Core 选择不同的合法自定义端口并启动 MicroVM
- **THEN** 两个选择的回环入口分别到达正确 Guest 端点，正常六路并发可完成，默认端口不被额外占用，不新增非回环监听或其他转发。

#### Scenario: 各平台交付产物与实际修复一致
- **WHEN** 构建并运行 Windows 或 Linux 的 CLI 或 GUI 交付产物
- **THEN** 实际加载的转发依赖与本次已校验的该平台构建输入一致，旧缓存或同名旧 DLL／SO 不能被当作修复结果；对应源码及许可证按现有交付规则可核对。
