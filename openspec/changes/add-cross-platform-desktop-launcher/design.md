# Design

## Context

动机与范围见 [proposal.md](proposal.md)。本变更跨共享运行服务、原生桌面、前端和单文件构建，并新增 Wails 依赖，因此需要本设计。

以下实现和环境信息来自最初规划，不能作为修复后产物已通过的证明。本轮按已确认范围重开 C1/W1–W5 及真实 GUI 验收，并新增语言和自身诊断任务；详细历史发现保留在 `verification.md`，不会因更新规划而改写为通过。

## Goals / Non-Goals

**Goals:**

- 由同一运行内核支撑 CLI 与 GUI，保留现有数据格式、写者独占、上游授权和 VM 行为。
- 把 GUI 的可点击状态建立在后端事实和并发控制上，启动/停止均不阻塞窗口响应。
- 先验证 Wails 主体与文件尾 bundle 共存，再完成两平台可运行产物及真实桌面 CoreLoop。
- 全部应用自有文案覆盖英文和简体中文，无语言偏好时固定英文，语言切换与 VM/安装状态独立。
- 不依赖 Guest/Core 成功启动即可取得 Launcher 自身真实诊断，并让用户在 GUI 导出本地包自行发送。

**Non-Goals:**

- 不建立新的管理 HTTP 服务、Infra Daemon、CLI 子进程协议或托盘后台运行模式。
- 不把 Piwork WebUI 放进 Launcher，不提供账户、模型密钥、Runtime、CPU/内存/端口设置页。
- 不增加文件共享、迁移旧盘、自动升级或安装器；现有 CLI 发布目标和公开发布动作不在本变更中扩展。
- 不更新 Piwork/Guest 锁定输入，不在本变更适配 `piwork-serve` 到 `piwork-core`；上游升级和其最终整合验收另立变更。
- 不建立上传接收端、遥测或自动日志发送；不翻译第三方技术日志或接管操作系统原生文件列表/系统按钮语言。

## Decisions

### D1. 独立 Wails 入口，纯 Go 桌面控制器

新增 `cmd/piwork-launcher`，包含 Wails 配置、入口和嵌入式静态前端。Wails 依赖固定为本轮查到的 v2 稳定版 **v2.17.0**（模块声明 Go 1.25.0，与当前 Go 1.25.5 可配合）；CLI 与 Go module 使用同一固定版本，不使用浮动 `latest` 构建。

新增 `internal/desktop` 管理状态、偏好和日志，用小型桌面适配接口隔离原生对话框/剪贴板/浏览器/窗口及事件发送。Wails 专有导入留在带桌面构建 tag 的入口适配层，使默认 `go test ./...` 和 CLI 构建不需要 GTK 开发库。前端使用 Wails 注入的绑定与 Runtime，不增加自定义 HTTP/RPC 服务；静态资源直接 `go:embed`，不需要 NPM/Vite 构建，也不引入前端框架。

备选：把 Wails 导入塞进 `internal/launcher` 会扩大 CLI 的依赖；启动 CLI 子进程再解析输出会复制控制流程且无法可靠表达关机结果，均不采用。

### D2. 从现有阻塞运行函数抽出上下文接口

CLI 保留 `Run(args, stdout, stderr)`，负责参数/帮助/版本和 `signal.NotifyContext`，随后调用共享运行方法。共享方法接收明确选项、调用方 Context 与观察器，返回实际结果；GUI 自己创建可取消会话，不安装 CLI 的信号处理器，不调用 `os.Exit`。

可采用 `RunContext(ctx, Options, Observer) error` 的最小接口；具体类型名由实现确定。运行选项保持默认 2 CPU、4096 MiB、17891/17871，GUI 设置禁止自动打开浏览器。`LocateBundle` 继续使用同一 `bundle.Locate()`，版本以类型化信息供 About 使用，不解析 `--version` 文本。

结构化事件至少包含会话 ID、递增序号、状态/阶段、WebUI 可访问、业务 Runtime ready、安装根/镜像/日志位置、实际 URL、经脱敏的错误及 clean/unclean 结果。新增资源检查/提取/磁盘准备事件从实际调用边界发出，Guest 阶段仍来自 QGA。日志与事件不可由 CLI 文本反向解析。

观察器只短暂更新控制器快照并写入有界日志缓冲/事件队列；独立分发器发送 Wails Events，不能在 VM 输出扫描或关机路径中等待 WebView。前端先订阅再读取 `GetStatus()`；事件和 RPC 快照共用跨会话可比较的 revision 或等价过期保护，不仅比较同一会话内 seq。新会话开始后，旧会话的迟到事件/旧快照不得恢复运行状态或启用浏览器按钮；日志同样按所属会话过滤。重连/初次载入用快照恢复，不高频轮询（W2）。

备选：彻底重写为多层 VM 管理器会增加改动，本次只抽出当前已经验证的顺序逻辑。

### D3. 明确状态机，WebUI 健康不等于业务配置完成

```text
idle --> starting --> running --> stopping --> idle
           |            |           |
           +--> error <--+-----------+
                  |
                  +--> starting
```

`stopping` 也覆盖启动中取消后的有界收尾。错误是否允许重试/换目录由“本次写者已全部退出”决定，不能仅靠前端按钮禁用。

| 状态 | 主操作 | 显示事实 |
| --- | --- | --- |
| idle | 启动 Piwork | 默认/已选安装根；未完成时显示目录选择 |
| starting | 无可执行 WebUI 操作 | 正在启动 Piwork、真实阶段、折叠日志 |
| running | 打开 Piwork | 实际 WebUI URL、镜像路径、复制、低权重停止 |
| error | 重试启动 | 后端原因、查看日志；收尾完成后可换目录 |
| stopping | 无重复停止操作 | 正在安全关闭 Piwork、真实收尾阶段 |

运行仅由当前 QEMU 存活加 `/healthz` HTTP 200 推进。首次 Core 尚未配置不阻止用户打开 QuickStart；`runtimeReady` 作为独立事实保留，不能把模型未配置说成启动失败，也不改变已配置安装的现有 ready 检查和失败处理。QEMU 意外退出立即使浏览器操作失效。

### D4. 并发与退出由后端统一裁决

桌面控制器持有一个会话、取消函数和完成信号。Start/Retry/Stop 在同一互斥状态机中串行决策，长操作在锁外运行；重复 Start 不创建 goroutine/VM，重复 Stop 复用现有操作。新会话只能在原会话真正结束后产生。错误收尾与 Stop 对取消请求和最终结果的读取/写入采用同一同步保护，补 Guest 错误与 Stop 同时发生的 race 回归（W1）。

GUI Stop 与运行中退出使用 Wails 原生确认对话框；Help/About 继续采用原型的轻量模态。这样窗口管理器关闭和自绘关闭按钮能共用同一个后端确认，而不依赖某个前端 click 处理器。Wails `OnBeforeClose` 在仍有会话时阻止立即退出，异步执行确认/停止，不能阻塞原生事件线程；仅在 safe 结果后设置一次性退出放行标记并调用 Runtime Quit。idle 可直接退出；正在确认/停止时重复操作合并。

取消启动通过共享 Context 传播；创建 QEMU 前检查取消，创建后走原有独立关机预算。不得用 `exec.CommandContext` 让 GUI Context 取消直接终止 QEMU。只有现有异常预算耗尽逻辑可以强制结束，并必须保留 unclean 诊断。发生未确认关闭时留在错误态供用户查看，不用自动关窗掩盖；本次写者仍在时禁止重试。

QEMU 进程一旦创建就属于受管生命周期，即使 Windows QGA/QMP 尚未连接，也必须把调用方取消/连接错误交给同一独立 120 秒收尾流程；不能在连接错误分支直接 Kill 后当作“未创建 VM”。创建事实和明确 clean/unclean 结果须跨越该初始化边界传回控制器；包装的 `context.Canceled` 本身不证明磁盘已同步，不得据此清理异常标记或提前正常 Quit。补延迟控制管道连接时取消/关闭的回归与 Windows 实机验收，核对锁、标记和进程释放（C1）。

Windows GUI 的 `windowsgui` 主体与 QEMU 子进程都需隐藏多余控制台；后者在现有平台 Start 配置上增量适配，不能覆盖 ACL、token、继承锁句柄、进程组或 Job。跨进程仍依靠现有磁盘锁，不增加接管另一 CLI/GUI VM 的协议；Linux 强杀后的存活写者和 Windows Job 联动退出继续遵循原语义。

### D5. 偏好保存在配置目录，完成标记绑定健康事实

建议偏好位置为 `os.UserConfigDir()/piwork-microvm/launcher.json`，采用私有权限/ACL、临时文件、sync 和原子替换。字段包含版本、选定的绝对数据根、已确认成功的安装身份及可选语言 `en`/`zh-CN`；不保存业务凭证，不写到 `--data-dir` 里面，也把 WebView 缓存留在独立用户缓存位置。

旧偏好缺少语言字段时按英文读取，不自动依据系统 locale 变中文，不迁移业务盘。语言选择与数据根/安装身份分开更新，健康完成标记和目录选择保存也必须保留已有语言，防止异步写回覆盖。语言保存失败保留原有有效选择并给出已本地化错误，不能假报保存成功；语言切换运行时可用，不启动/停止 VM、不改变安装完成状态。

没有偏好才使用 `platform.DefaultData()`；原生选择后先验证可接受的本地路径并成功保存，再更新界面。取消或保存失败不改变有效选择。现有 CLI 用户直接沿用默认/所选旧盘，首次 GUI 健康确认前仍可显示目录设置；这不影响旧盘内容。

成功标记只在已收到当前 WebUI 健康事件、且有效安装身份可读后写入。重开时核对路径/身份和磁盘，不单靠 preferences 布尔值或 `stage=ready`。失败态在写者结束后允许重选，即使此前某次成功，也不能通过隐藏设置阻止修正目录。偏好损坏明确报错，不能静默创建另一空安装。

Linux 现有私有目录检查要求 0700，而文件选择器新建空目录常为 0755：GUI 只可在用户明确选定的、由当前用户拥有的空目录上于启动准备时收紧为 0700，再进入原检查；不递归 chmod，不放宽 CLI 检查，不更改已有非空安装的权限或未知内容。不满足条件则给出真实原因。新盘复制、坏盘/缺盘拒绝覆盖全部仍由现有 `prepareDisk` 完成。

### D6. 直接迁移原型，替换模拟行为和远程资产

前端资源位于 Wails 入口下的静态目录，保留原型的 Header、主内容、日志和轻量弹窗布局，移除页面外的预览容器；实际窗口区域使用视口布局而不是再套一层固定 800×600 页面框。CSS 复用上游 Tokens/Controls，桌面专用样式只负责布局、拖动区域和紧凑适配。复制上游文件时记录 commit、内容 hash 和许可，不在运行时访问相邻源码或 GitHub。

Header 使用本地 Logo、Piwork 和 Launcher 标识；Wails Frameless 与 `--wails-draggable` 只覆盖标题空白区域，按钮及其后代、菜单和模态明确 no-drag。最小化使用真实 Runtime；关闭统一进入 D4。使用 Wails/系统支持的无边框装饰和原型圆角/边框，不为视觉引入新的窗口管理依赖。

删除原型 `stateLogs`、`phaseLines`、preview 状态切换、平台模拟、启动/停止定时器和 `installed=true` 演示赋值。动画 spinner 和复制反馈的短暂提示可保留，但不能驱动生命周期。所有操作 SVG 本地提供；外部 URL 通过后端允许的菜单目标及系统浏览器处理，不能让前端任意导航替换 Wails 页面。

应用保持一个状态一个主操作，不增加高级设置。日志展开时内容区/日志区有独立高度约束，长中文/空格路径省略并可复制，不使窗口产生横向溢出；800×600 时主操作、菜单和对话框仍可达。

### D7. 展示缓冲、完整导出与 Launcher 自诊断分离

仍使用 `<data-dir>/logs/<UTC timestamp>.log`。GUI 从共享写入路径得到真实日志事件和当前日志文件身份，并显示有界的最近内容；不把敏感 QEMU 输出先送到前端再过滤。将现有 `sensitiveLine` 规则整理成共享脱敏入口，用于输出、错误、历史文件读取及导出。页面写入使用文本节点，不能把日志作为 HTML。

`ReadLogs()` 读取当前会话，重开时可明确显示当前安装最近的历史日志；只保留有限行数/字节，避免大日志卡死。展示缓冲不是“导出本次日志”的数据源；导出从真实当前会话文件取得导出开始时已写入的完整内容并再次脱敏，不能丢失超出展示行数/字节数的部分。超过导出大小上限须明确报错，不能把尾部或截断文件当作完整导出（W3）。若 VM 会话日志尚未创建，该导出项仍不可用；独立的真实 Launcher 诊断可以使用下面单独标识的入口。

导出本次为 `.log`，全部为 `.zip`，仅归档选定安装 `logs/` 中的真实常规日志文件，逐行重新脱敏。两个导出项分别依据 `currentAvailable` / `allAvailable` 启用；有历史但无本次时仍可导出全部。调用 Wails SaveFileDialog，取消不写入；保存失败展示错误，导出不能覆盖源日志、程序或安装数据。导出不带磁盘、数据库、preferences、QGA/QMP 材料或其他安装的日志。

保存目标只要求父目录存在且对当前用户可写，不把安装根的 0700 检查套到 Downloads/Desktop，也不修改其权限。临时输出文件使用私有权限/ACL；完整写入、sync 和关闭都成功后才原子替换目标，任何步骤失败都传回真实错误、删除临时文件并保留旧目标。分别测试 Linux 普通 0755 可写目录、实际部分写入/同步失败，而不只测试创建文件失败（W4/W5）。

在 GUI/桌面运行时初始化之前尽早写真实 Launcher 自诊断到独立用户位置，建议 `os.UserCacheDir()/piwork-microvm/diagnostics/`，不依赖可写安装根、资源提取、QEMU 或 Core。底部日志导出菜单增加最小的本地诊断包入口，清楚标识来源；包只含本次 Launcher 的脱敏诊断及必要版本/平台/失败阶段信息，不扫描其他安装或带业务盘、凭证及控制材料。若窗口初始化失败而程序已执行，文档给出真实诊断文件位置；若系统加载器在 Go 入口前即拒绝执行，或连诊断位置也不可写，应如实说明无法生成文件并提供系统错误获取步骤，不能伪造已保存日志。

用户在 GUI 保存诊断包后自行发给维护者。应用不上传日志、不要求上传地址，也不引入接收服务；原始技术日志保留原文，应用自有说明和导出结果按 D10 本地化。

备选：沿用原型的浏览器 Blob 下载无法满足原生保存对话框，直接归档历史字节会绕过新增脱敏，因此均替换。

### D8. 先证明 Wails 与 Trailer 兼容，再接通正式构建

先进行最小构建关口：用固定 Wails、静态嵌入页面和现有 bundle 资源生成 Linux/Windows 桌面主体，完成 Wails 资源/图标/版本处理后再追加归档、manifest 和 64 字节 Trailer。在原生平台打开窗口，并证明 `bundle.Open/Locate()` 能从该最终文件读到自身资源。此步骤不宣称已完成 GUI CoreLoop。

正式构建采用独立 Wails 入口配置。Makefile 增加 `piwork-microvm-gui`、`piwork-microvm-gui-windows` 和 `piwork-microvm-gui-all`；这些目标显式覆盖 GUI 所需 CGO，而现有全局 CLI 默认继续为 0。Linux 基线使用 GTK3 + WebKitGTK 4.1，配套 `webkit2_41` tag，文档列出开发包和运行库。Windows 优先通过原生 Go/MinGW 构建隐藏控制台的 PE，再由公共脚本完成封装；从 WSL 发起构建不是 Windows 运行依赖。

`scripts/bundle.py` 增加默认仍为 CLI 的入口选择，复用公共资源集合、许可证、版本注入及追加过程。GUI 主体由 Wails/桌面构建适配生成，不调用原来固定的 CGO=0 CLI 编译命令。主体、中间包、manifest、产物和 `.sha256` 按入口/平台命名，不能覆盖 CLI 对应文件；最终名称为 `dist/piwork-microvm-gui[.exe]`。

Wails 的 Windows 资源处理和 Linux strip 等都必须在资源追加之前；追加后不再进行 UPX、strip、资源修改或改变 EOF 的签名处理。Linux GUI 动态链接 Host 的桌面系统库，QEMU 继续由自己的 loader/library-path 启动，不全局设置可能污染 GTK 的 QEMU 库路径。WebView2/GTK 缺失是桌面系统前提错误，不回退 CLI 或下载 MicroVM 资源。

GUI About 复用包装层自身版本及上游版本/commit，构建附带新增依赖的许可。GUI 本地构建记录包含入口类型、包装层源码和前端输入、Wails/Go/桌面工具链、Guest 锁定输入以及实际产物 hash；不把 GUI 信息写成上游 Piwork 的版本，也不改变当前 CLI `make release` 的发布资产。

英文/简中词条与前端一同嵌入最终文件，不新增翻译服务或运行时下载。此处构建和验收只对应现有锁定输入的 GUI 阶段；后续升级上游后的重建、缓存身份核对和最终整合交付另由独立变更承担。

| 层次 | 检查内容 | 可证明的范围 |

截图至少有未启动、真实启动中、真实运行和受控端口占用等真实错误，并补充停止中、日志展开和菜单/弹窗检查。故障应由真实外部条件触发，不能通过前端 preview 开关制造；构建关口可使用单元 fixture，但不得写成真实 VM 验收。

修复后重新执行 C1/W1–W5 的针对性回归；两平台各自验证英文默认、切换/重开保存、两种语言的 800×600 五态与原生操作、完整日志和自身诊断包获取。Windows 延迟控制通道时取消必须单列，不能以取消发生在创建进程前的结果代替。用真实端口冲突等条件验证 VM 未启动仍可从 GUI 导出本次自身诊断，打开包核对真实来源、完整性与脱敏。历史记录保留原时间/输入/产物身份；未重跑或环境不可用的项目仍待验证。

记录分别列出本次运行的文件身份、平台/桌面库、锁定输入和结果。遵循仓库当前发布约定：输入级验收与下载物校验和分别表达，不把历史 CLI 证据自动归给 GUI，不把重建后的新字节宣称为此前实际运行过。不能打开窗口或主路径仍阻断时，不声称 GUI 完成。

### D10. 英文默认的本地双语目录与用户文档一致性

只支持 `en` 和 `zh-CN`，应用自身的界面、状态/阶段说明、已知错误说明、菜单、工具提示、无障碍标签、复制/保存反馈、Help/About 和提供给原生对话框的标题/正文/筛选器名全部从本地词条读取。无偏好时固定英文，既有偏好按 D5 兼容；初次显示不能根据系统语言自动改为中文。现有“更多”菜单提供 `English` / `简体中文`，切换立即更新应用文案，无额外设置页或首次必选步骤。

结构化阶段与错误上下文用于本地化，不翻译日志以推断状态，也不翻译/破坏路径、URL、版本或外部技术诊断。原生日志保留原文；操作系统提供的原生按钮、文件列表和系统错误仍由系统控制，应用可控文案不能借此保留硬编码单语。切换语言和重绘保持当前生命周期、日志展开及错误事实。

英文 README 与简中 README 及 GUI 帮助的操作名称与对应语言一致，构建目标、依赖、两端口、数据/日志/诊断位置、导出边界、权限、排障、交付身份和未测限制逐项对齐。引导文档随所选语言打开对应 README；仓库/Discuss 链接保持不变。语言和文档更改不翻译或改造 Guest 内原版 Piwork WebUI。

## Risks / Trade-offs

- [GUI 生命周期抽取改变 CLI 收尾] → 原来的有序逻辑保留为唯一实现；先补状态/取消的针对性测试，再分别复验 CLI 和 GUI 原盘恢复。
- [磁盘 `ready` 早于服务就绪] → 完成标记必须由当前健康事件加安装身份形成，失败及中断测试覆盖这一时间窗。
- [原生回调或日志阻塞界面/关机] → 退出协调异步、有界日志和事件队列、独立关机 Context、快速一致状态快照。
- [无边框程序退出使 Windows Job 提前关闭] → Wails 真正 Quit 前等待会话结束，保留现有 Job/继承锁，并验证强制结束时的 unclean 行为。
- [GTK/WebKit 动态库使 GUI 不等同 CLI 的运行依赖] → 文档、构建配置和实际库检查分开；Linux 桌面依赖只对 GUI 生效，CLI 仍无 CGO。
- [Wails 资源处理改变尾部] → 最早执行兼容关口，所有二进制处理放在 Trailer 之前，最终文件按平台验证自身读取。
- [原型、上游样式和锁定 Guest 来自不同输入] → 固定并记录 UI 文件来源和 hash，UI 资产复制不刷新 Guest pin，不在运行时加载外部原型。
- [800×600 展开日志时压缩内容] → 主区域可控滚动/紧凑布局，实际窗口截图检查状态、长路径和模态；不靠扩大初始窗口掩盖问题。
- [语言偏好被安装完成或选目录的异步保存覆盖] → 独立字段更新、原子持久化和并发回归，保留安装身份与既有选择。
- [双语遗漏或外部日志被误翻译] → 词条完整性与硬编码检查，真实窗口检查应用文案，第三方技术输出明确保留原文。
- [VM 未启动无安装日志，或窗口无法初始化] → 独立的早期 Launcher 真实诊断、GUI 本地包导出及文件位置说明；系统加载前失败如实保留系统排障边界。

## Migration Plan

不迁移业务数据或改盘格式。新 GUI 使用原默认目录或用户选择的现有安装根；首次 GUI 健康成功后只新增独立配置目录中的偏好记录。回退时继续使用现有 CLI 与同一已安全停止的数据盘，GUI 偏好和 WebView 缓存可以单独移除，不能清理业务盘。

已有偏好无语言字段时兼容为英文，用户明确选择后持久化；修改语言不创建另一安装或重写原盘。按已确认任务重开受影响的修复/回归，先完成生命周期、并发和导出修复，再实施语言与诊断，交叉核对双语文档后完成两平台真实 GUI 验收。现有上游 pin 不变，后续升级变更另行处理 `piwork-serve` 到 `piwork-core` 的入口和参数适配。

规格/规划单独提交；各项功能代码与针对性测试、跨功能用户文档、验收记录按 AGENTS 分别组织提交，不虚构既有未提交实现的开发历史。本轮只提交已确认规划并停止，后续实施等待单独 apply；不推送、发布或自动归档。
